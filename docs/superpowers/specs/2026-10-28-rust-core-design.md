# hushkey core in Rust: a C-ABI library, continuous listening and voice commands

## Why

hushkey is a push-to-talk dictation app. Other programs cannot use it: the
speech recognition lives inside a Python daemon that only types into the
focused window. The first concrete user is a lab colleague at a plug board who
tests 100 contacts of a chip with both hands busy. He wants to say "weiter" or
"Kanal 6" and have his test UI switch channels, without reaching for the mouse.
The next one is an assistant running on a local machine: talking to it in a
voice mode, with every word staying on local machines.

So hushkey's recognition becomes a library with a C ABI that any language can
load (C, C++, C#, Python via ctypes, Go, Rust), plus a mode that listens
continuously and turns speech into events: utterances, fixed commands, and
replies from an exchangeable "brain" (an OpenAI-compatible server; anything
else through a host callback).

## Goals

1. **Core library** (`hushkey-core`): microphone capture, whisper.cpp
   transcription (CPU, Vulkan, Metal, CUDA via features), push-to-talk sessions
   with a live preview and a final transcript, and file transcription.
2. **C ABI** (`hushkey-ffi`): a `cdylib` + `staticlib` and a committed
   `include/hushkey.h` generated by cbindgen. Opaque handles, plain C structs,
   one event callback, thread-local error text, an ABI version number.
3. **Continuous listening**: start/stop listening; Silero VAD (whisper.cpp's)
   finds utterance boundaries; each utterance is transcribed and delivered as
   an event, with preview events while it is being spoken.
4. **Voice commands**: a command set (JSON) maps phrases with slots
   (`"kanal {n}"`) to named commands; numbers in digits or German/English words;
   tolerant matching. Command phrases are fed to whisper as a prompt so short
   words are recognized reliably.
5. **Brain adapters** (`hushkey-brain`): an utterance that is no command goes to
   a configured brain, and its reply arrives as an event. The adapter shipped
   is OpenAI-compatible chat completions (llama.cpp server, vLLM, Ollama,
   ChatGPT), with Bearer token and an own-CA option; any other assistant is
   implemented by the host against the `Brain` trait or the C callback. The
   session keeps the conversation history.
6. **CLI** (`hushkey-cli`): `transcribe <wav>`, `record` (Enter to stop),
   `listen [--commands file] [--openai url ...]`, printing events. This is the
   demo and the integration test harness.
7. **App port** (phase 4, own design note when it starts): hotkey, paste with
   clipboard restore, tray, as a Rust binary using the core.

## Non-goals

- Replacing the Python app before phase 4 reaches parity. The Python hushkey
  stays the shipped product and keeps working unchanged throughout.
- Speech output (TTS). The reply event carries text; a host may speak it.
- A network server inside the library. Hosts decide how to expose it.
- Wake words. Listening is started and stopped explicitly.
- Executing actions. A brain reply is text; whatever approves and runs tasks
  stays in the host.

## Anti-goals (failure even if it works)

- Audio or text leaving the machine without the host configuring a brain URL.
- A command firing on something that was not said: matching must prefer "no
  command" over a doubtful match, and report the matched phrase.
- A slow command: from end of speech to the command event should stay well
  under a second on a GPU with a turbo model.
- Callbacks that deadlock when the host calls back into the library.

## Constraints

- Rust stable (1.85+), edition 2021. Windows x64, Linux x64/arm64, macOS
  arm64/x64.
- whisper.cpp through `whisper-rs` 0.16; GPU backends behind cargo features so a
  CPU build needs no SDK.
- Models: GGML files, resolved from a path or from the Hugging Face cache
  (`ggerganov/whisper.cpp`, `ggml-org/whisper-vad`), optional download.
- The C ABI is the contract: additive changes only within an ABI version;
  every struct carries its size so it can grow.

## Shape of the C API (decided)

```c
uint32_t hk_abi_version(void);
const char *hk_last_error(void);            /* thread-local, valid until next call */

HkEngine *hk_engine_new(const HkEngineConfig *cfg);   /* loads the model */
void hk_engine_free(HkEngine *);
char *hk_transcribe_file(HkEngine *, const char *wav_path, const char *language);
char *hk_transcribe_pcm(HkEngine *, const float *samples, size_t n, const char *language);
void hk_string_free(char *);

HkSession *hk_record_start(HkEngine *, const HkRecordConfig *, HkEventCallback, void *user);
int hk_record_stop(HkSession *);            /* emits FINAL, then frees the session */
HkSession *hk_listen_start(HkEngine *, const HkListenConfig *, HkEventCallback, void *user);
int hk_listen_stop(HkSession *);
```

Events (`HkEvent`): `PREVIEW`, `FINAL`, `SPEECH_START`, `UTTERANCE`, `COMMAND`
(name + args), `REPLY`, `ERROR`, `STOPPED`. Strings inside an event are valid
only during the callback. Callbacks run on a library thread; calling
`hk_*_stop` from inside a callback is allowed and does not deadlock.

## Left to the builder

Thread layout, resampling method, VAD window sizes, matching algorithm and
thresholds, error codes, CLI flags beyond the ones above, CI layout.
